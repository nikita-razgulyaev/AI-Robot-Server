# Поведение Сорена: датчики опоры, события, правила

Краткое описание того, что реализовано, где это лежит и что можно править руками. Планы помечены отдельно.

## Как это работает (в двух абзацах)

Плата ESP32 читает **две тактовые кнопки** (в лапе и в крыле) и при любом изменении шлёт серверу `{"type":"sensor","paw":bool,"wing":bool}`. Никаких реакций на самой плате нет. Сервер (`modules/behavior.py`) складывает кнопки в **состояние опоры**, подтверждает его по времени (защита от дребезга), выводит **событие** и ищет подходящее **правило** в `character/behavior/rules.yaml`. Реакция (анимация, эмоция, короткая фраза) идёт через **арбитр** (`modules/arbiter.py`): падение берёт приоритет `SAFETY` и перебивает любое текущее движение.

Анимации — обычные JSON-файлы `character/animations/*.json` (кадры `{time, servos[22]}`), их проигрывает уже существующий `ServoController`, а плата сглаживает движение интерполяцией. Эмоции и фразы используют существующие `Soren_emotions.json` и `quick_answers.json`.

## Состояния опоры

| Лапа | Крыло | Состояние | Значение |
|---|---|---|---|
| нажата | нет | `standing` | стоит на опоре |
| нет | нажато | `held` | держат в руках на весу |
| нажата | нажато | `held_touch` | держат, лапа касается опоры (ставят/берут) |
| нет | нет | `none` | опоры нет: полёт, прыжок или падение |
| — | — | `unknown` | данных от кнопок ещё нет (плата не подключена) |

Различить падение и собственный полёт позволяет флаг «сам взлетел»: он ставится командой `takeoff` и действует до касания, до того, как робота взяли в руки, или `self_flight_timeout_sec` секунд.

## События

| Событие | Когда |
|---|---|
| `support_lost` | стоял → опоры нет |
| `released` | держали → отпустили в воздухе (опоры нет) |
| `grabbed` | взяли с опоры или подхватили в воздухе |
| `touchdown` | из «опоры нет» → лапа коснулась |
| `support_regained` | держали → поставили на опору |

Переход `held` ↔ `held_touch` событий не создаёт. Подтверждение по времени: `behavior.confirm_ms` (40 мс) для обычных переходов, `confirm_none_ms` (80 мс) для «опоры нет». Дебаунс самих кнопок (20 мс) делает прошивка.

## Где что править

| Что менять | Файл | Применение |
|---|---|---|
| Реакции на события (кто, когда, что делает) | `character/behavior/rules.yaml` | `POST /behavior/reload` |
| Движения (кадры, углы, время) | `character/animations/*.json` | `POST /animations/reload` |
| Короткие реакции голосом | `character/quick_answers.json` (записи `behavior_*`, `triggers: []`) | `POST /quick_answers/reload` |
| Эмоции и позы эмоций | `character/Soren_emotions.json` | перезапуск |
| Тайминги подтверждения, окно «сам взлетел», вкл/выкл | секция `behavior:` в `config.yaml` | перезапуск |
| Пины кнопок, полярность, дебаунс | `firmware/esp32_ai_robot_server.ino` (`PAW_BUTTON_PIN`, `WING_BUTTON_PIN`, …) | перепрошивка |
| Кинематика ходьбы/полёта/взлёта/посадки | `modules/motion_primitives.py` (сейчас заглушки, значения из чек-листов) | перезапуск |
| Приоритеты источников | `modules/arbiter.py` (`Priority`) | перезапуск |
| Микродвижения («дыхание» 1–2°) | секция `micro_jitter:` в `config.yaml` (по умолчанию `enabled: false`) | перезапуск |
| Мёртвая зона серво и шум в Serial | `SERVO_DEAD_ZONE`, `LOG_SERVO_FRAMES`, `SUPPORT_BUTTONS_ENABLED` в прошивке | перепрошивка |
| Подробный лог кадров серво на сервере | уровень логирования `DEBUG` (по умолчанию кадры не печатаются) | перезапуск |

Формат правил описан в шапке `rules.yaml`. Правила проверяются сверху вниз, срабатывает первое подходящее. Если анимации из правила нет, выполнятся остальные части правила, в логе будет предупреждение.

## Файлы

| Файл | Роль |
|---|---|
| `firmware/esp32_ai_robot_server.ino` | чтение кнопок, дебаунс, `sensor`-сообщения, кнопки в `device_state` |
| `modules/behavior.py` | состояние опоры, события, правила, флаг «сам взлетел», `can_takeoff()` |
| `modules/servo_controller.py` | `cancel_current()` — прервать текущую анимацию, не сбрасывая позу |
| `modules/robot_brain.py` | `takeoff` разрешён только из `standing` (если данные кнопок есть), ставит флаг «сам взлетел» |
| `websocket_server.py` | приём `sensor`, `device_state`, сброс при отключении платы, `/behavior/reload`, `behavior` в `/status` |
| `character/behavior/rules.yaml` | таблица правил |
| `scripts/test_behavior.py` | тест логики без железа |
| `docs/checklists/` | чек-листы углов для взлёта/посадки и ходьбы/полёта/реакций |

## Статус

**Готово:** состояние опоры из двух кнопок, события, подтверждение, правила с hot-reload, арбитраж, запрет взлёта без опоры, фразы-реакции, тест логики.

**Ждёт данных от тебя:** анимации `fall_react`, `grabbed_react`, `recover_stand`, `settle_after_put` (из чек-листа, раздел D) и кинематика `TAKEOFF`/`LANDING`/`SINGLE_STEP`/`SINGLE_FLAP`/`SINGLE_TURN_TICK` в `motion_primitives.py`. Пока анимаций нет, правила только меняют эмоцию и играют фразу.

**Не реализовано (план):**
- IMU/барометр: ориентация (вниз головой), высота, удар, плавная потеря опоры. Добавятся новые события и условия в `rules.yaml`.
- Модель эмоций по трём осям (приятно/активность/контроль) с затуханием и настроением; пока используются 9 эмоций из `Soren_emotions.json`.
- События зрения и звука в той же таблице правил (знакомое лицо, громкий звук, пауза в диалоге, скука); сейчас они живут в `robot_brain.py` и `idle_thoughts.py`.
- Передача состояния опоры в контекст LLM.
- Аппаратные рефлексы на плате (сознательно не делаются): при потере связи плата сама ничего не предпринимает.

## Известные особенности

- Файлы `character/animations/head.json`, `legs.json`, `tail.json`, `wings flap.json` записаны в старом формате на 18 серво, а загрузчик требует ровно 22, поэтому они пропускаются при старте (в логе ошибки). Индексы серво с тех пор поменялись, автоматически перенести их нельзя.
- Скорость серво ограничена прошивкой: не более 3° за 10 мс (300°/с) с замедлением у цели (`SERVO_MAX_STEP`, `SERVO_EASE_FACTOR`). Быстрые махи крыльями упрутся в этот предел.
